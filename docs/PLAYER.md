# 플레이어 내부 구조

웹 플레이어(`player/`)가 어떻게 동작하는지, 원본 유씨노벨 플레이어와 무엇이 같고 다른지 정리한 문서입니다.
파일 포맷 자체는 [`UCN_FORMAT.md`](UCN_FORMAT.md)를 보세요.

## 근거 자료

| 자료 | 내용 |
|---|---|
| 작품 파일 1개 | `de46dac1-1.ucn` (25.4MB, 210장, 엔트리 84개, 2019년 8월 작성) — 포맷 역공학과 모든 테스트의 기준 |
| 공식 안드로이드 플레이어 1.0.6 | `air.com.ucnovel.player` (Adobe AIR). `assets/UCMobilePlayer4.swf`의 ActionScript 바이트코드를 직접 역어셈블해 텍스트 출력·태그·설정 기본값을 확인 |

원본 코드에서 확인한 클래스: `UCPlayer`(장 이동), `UCScenario`(텍스트 출력), `UCActionTag`(`$`/`#` 태그), `UCscriptParser`/`UCscriptLibrary`(작품 스크립트), `UCDataManager`(독자 설정), `UCComponentLayer`(컴포넌트).

## 모듈

스크립트는 `index.html`에서 아래 순서로 불러오며, 모두 전역 객체 하나씩만 노출합니다(모듈 번들러 없음, `file://`에서도 동작하도록 일반 `<script>` 사용).

| 파일 | 전역 | 역할 |
|---|---|---|
| `log.js` | `Log` | 로그 수집·구독, `window.onerror`/`unhandledrejection` 기록 |
| `ucn.js` | `UCN` | `UCN.load(File)` → `{ story, files, urls }`. 컨테이너 해제, XML 해석, 타임라인 구성, `UCN.crc32` |
| `player.js` | `Player` | `start(data)`, `begin()`, `advance()`, `back()`, `go(index)`, `restart()`, `page` |

| `index.html` 인라인 | – | 첫 화면 상태, 끌어다 놓기, 도구 막대·로그 창, 키보드·클릭 연결 |

## 불러오기 단계 (`UCN.load`)

1. 파일 전체를 `ArrayBuffer`로 읽음.
2. 앞 16바이트를 로그에 기록. 16바이트 위치에 엔트리 헤더(`UC`/`PK` + `03 04`)가 없으면 파일 전체에서 첫 헤더를 찾음.
3. 엔트리마다: hex 파일명 디코딩 → 범위 확인 → CRC32 확인(불일치는 경고) → `DecompressionStream('deflate')`로 zlib 해제(실패하면 압축 안 된 데이터로 간주) → 성공/실패 기록. **한 엔트리가 실패해도 다음 엔트리로 계속.**
4. 엔트리 뒤가 중앙 디렉터리(`PK 01 02`)인지 확인하고, 종료 레코드의 엔트리 수와 대조.
5. `script.xml`을 `DOMParser`로 해석해 장별 타임라인(`story`)을 만듦(아래).
6. 이미지마다 `Blob` URL 생성. 리소스에 있는데 파일에 없는 이미지는 오류로 기록.

## 타임라인 (`story`)

```js
{
  width, height,            // 화면 크기 (system/option size)
  font, fontSize,           // 기본 글꼴 이름, 글자 크기
  resources: { id: { type: 'image'|'back'|'bgm', file } },
  texts: { id: '원문' },
  pages: [{
    page,                                   // 1부터
    advance: { mode: 'click' } | { mode: 'auto', ms },
    background: Item | null,
    images: [Item],                         // z 오름차순, 같으면 문서 순서
    text: { text, x, y, width, height, align, color, vPadding, hPadding, leading, ... } | null,
    bgm: { key, ref, file, start, end } | null,
  }],
}
// Item = { key, ref, file, start, end, x, y, width, height, z, order, effects: { start, end } }
```

- 배경·이미지·BGM 노드는 `start`~`end` 모든 장에 들어갑니다. 같은 노드는 같은 `key`를 가지므로, 장이 바뀌어도 같은 노드면 다시 그리지 않습니다.
- `hidden="true"` 노드는 제외합니다.
- 첫 번째 `<scene>`만 사용합니다.

## 화면 합성 (`Player.renderLayers`)

- 무대는 `width × height`(기본 800×480) 고정 크기 요소를 창 크기에 맞춰 `transform: scale()`로 확대·축소합니다(비율 유지, 남는 영역 검정).
- 쌓는 순서: 배경(항상 맨 아래) → 이미지(z 순서) → 텍스트 상자 → BGM 표시 → 시작/끝 오버레이.
  - 표본 파일의 일부 배경 노드에도 `z` 값이 있지만, 그 값을 따르면 배경이 위아래 검은 띠 이미지를 덮어 버려 무시합니다.
- 전환 효과는 원본 `UCBackground`와 같은 **마스크 전환**입니다. 원본 효과 목록(`m_sMaskList`): `fade` `white` `hfade` `vfade` `hblind` `vblind` `hcurtain` `vcurtain` `hdoor` `vdoor` `circle` `four` `clock` `dust` `mirage` `water` `star` `drop` `vortex` `lens` `flare` `none`. 목록 순서 n번째 효과가 마스크 `e(n+1)`(원본 앱에서 꺼낸 320×240 흑백 JPEG, `masks.js`)를 씁니다.
  - 등장(`effect type="start"`): 사진의 불투명도 = 255 − clamp(마스크 + 10 + 기준값), 기준값은 효과 시간 동안 255 → −255. **마스크의 어두운 곳부터** 새 사진이 드러납니다.
  - 퇴장(`effect type="end"`): 반전한 마스크로 기준값 −255 → 255. 역시 어두운 곳부터 사라집니다(원본 바이트코드의 `pushbyte 255`가 부호 있는 −1, 즉 반전).
  - 구현: 전환하는 동안만 레이어 위에 캔버스를 겹쳐 사진을 마스크로 그리고, 끝나면 원래 이미지로 돌아갑니다. 마스크는 `file://`에서도 픽셀을 읽을 수 있도록 data URI로 넣었습니다.
  - `fade`는 투명도 전환, `none`/시간 0은 즉시. `white`(배경만): 흰 판이 불투명→투명으로 걷히며 등장, 투명→불투명으로 덮이며 퇴장(`UCBackground.whiteMaskEffect`). 표본 작품에는 없어 실제 파일로는 확인하지 못함.
  - 마스크 전환은 **배경에만** 적용됩니다(`UCBackground`). 이미지 레이어(`UCComponent`)는 `fade`일 때만 투명도가 바뀌고, 다른 효과 이름은 움직임만 있습니다.
- 효과 움직임(원본 `UCComponent.makeTween`·`UCBackground.makeTween`):
  - 위치: 등장은 제자리에서 (−x, −y)만큼 떨어진 곳에서 시작해 제자리로, 퇴장은 제자리에서 (−x, −y)로.
  - 크기: 이미지는 `width`·`height`가 %(100 = 그대로), 배경은 무대 픽셀 대비 비율. 등장은 그 크기 → 원래 크기, 퇴장은 원래 → 그 크기. 가운데 기준.
  - 회전: 등장만 `rotation`° → 0°(원본도 퇴장 회전은 동작하지 않음).
  - 곡선 `option`: 기본 Power1 감속, `accel` Power4 가속, `decel` Power4 감속, `over` Back 감속(살짝 지나쳤다 돌아옴), `hquake`/`vquake` 0.1초마다 10~15px 가로/세로 흔들림.
  - 효과 시간이 0이면 움직임 없음. 첫 표본 작품의 오프닝(2~15장): 인물 사진이 오른쪽에서 `over`로 들어와 `accel`로 왼쪽으로 빠지고, 이름 글자가 아래에서 `over`로 올라와 오른쪽으로 빠짐.
- 퇴장 효과가 없으면 새로 들어오는 요소의 등장 효과가 끝날 때까지 아래에 남겨 두어 검은 화면이 비치지 않게 함.

## 텍스트 출력 (`Player.run`)

원본 `UCScenario.printText`/`onComplete`/`runTag`와 `UCActionTag.convertTag`를 따릅니다.

| 원문 | 원본 동작 | 웹 플레이어 |
|---|---|---|
| `#p` | `\r`로 바꾼 뒤 줄바꿈과 동일하게 처리 | 동일 |
| 줄바꿈 | 줄 끝에서 클릭 대기(독자 설정이 "문단" 모드일 때) | 동일. 빈 줄은 대기 없음, 글 끝의 줄바꿈은 무시 |
| `#w;` | 같은 줄에서 클릭 대기 | 동일 |
| `#c;` | 다음 줄바꿈에서 대기하지 않음 | 동일 |
| `#d.N;` | N초 뒤 자동으로 이어감 | 동일 (클릭하면 건너뜀) |
| `#g.…;`, 기타 `#이름;` | 작품 스크립트 함수 호출 | 무시하고 로그에 경고 |
| `$이름;`, `$배열[i];` | 스크립트 전역 변수 값 | 작품 스크립트에 선언된 변수(입력창으로 채움)를 표시, 없으면 빈칸. 선언 안 된 변수는 로그에 경고 |
| `$`/`#` 뒤에 `;`가 없음 | 문자 그대로 | 동일 (예: `# 우주의 연하`) |

- 글자 속도: 원본 공식은 글자당 `(50 - speed/2)`ms이고 **100이면 한 줄을 애니메이션 없이 한 번에** 표시합니다. 노드의 `speed`가 0이면 독자 앱 설정(원본 앱 기본 70)을 따릅니다.
  파일의 `speed`는 **0~9 단계**로 저장되며 원본(`UCScenarioNode`)은 `speed ÷ 9 × 100`으로 바꿔 씁니다. 9 = 100 = 한 줄씩 바로, 1 ≈ 11 = 글자당 약 44ms.
  웹 플레이어는 독자 설정을 **100**으로 두어 한 줄씩 바로 표시하고, 노드에 0이 아닌 `speed`가 있으면 같은 변환·공식을 따릅니다(첫 표본은 모두 0, 둘째 표본은 대부분 9 → 바로 표시, 7개 장은 1 → 한 자씩).
- 클릭할 때: 출력 중이면 다음 대기 지점까지 즉시 출력 → 대기 중이면 이어서 출력 → 다 나왔으면 다음 장.
- 줄 배치: 원본처럼 **줄 전체로 자리를 먼저 잡고** 그 자리에서 앞부분부터 드러냅니다. 아직 안 나온 같은 줄의 나머지(`#w;` 뒤 글자 등)는 투명한 글자로 미리 배치해, 가운데 정렬에서도 이미 나온 글자가 옆으로 밀리지 않습니다.
- 텍스트 상자가 넘치면(원본의 최대 줄 수 도달) 현재 줄만 남기고 비운 뒤 이어서 출력합니다. 원본은 줄 수로 판단하고, 웹은 실제 높이 넘침으로 판단합니다.
- 스타일: 위치·크기·색·정렬·위아래 여백(`vPadding`)·좌우 여백(`hPadding`)·줄간격(`fontSize + leading`). 외곽선은 검정 1px 고정.
- 글창: 원본 `UCScenario.setProperty`처럼 텍스트 노드 영역을 `background` 색, 불투명도 `opacity`/100으로 칠하고, `border`가 있으면 `bordercolor` 1px 테두리, 모서리는 `radius`×4 지름(CSS `radius`×2)으로 둥글게. 첫 표본은 `opacity=0`(투명, 대신 레터박스 이미지 사용), 둘째 표본은 `opacity=100`(검은 글창).

## 이름 입력창

- 리소스: `<object type="image" advtype="input" background opacity border bordercolor radius btncolor btnbackground btnopacity>`. 그림 파일은 편집기용 자리표시라 표시하지 않음.
- 배치: 이미지 레이어 노드의 영역 안에 원본 `UCInput` 배치대로 입력칸(위쪽 40~80px)과 버튼(110~150px, 좌우 20px 여백)을 그림. 입력칸·버튼 배경은 `background`/`btnbackground` + 불투명도, 글자색은 `btncolor`.
- 넘김: 그 장의 `delay mode="button"` → 입력 대기. 화면 클릭으로는 넘어가지 않고, 빈 값은 받지 않음(흔들림 표시).
- 처리: 작품 스크립트(`<global><script>`)의 `void onInput[노드ID](string v) { … }`를 실행. 지원하는 문장: `변수 = v;`, `gotoPageNext();`, `gotoPagePrev();`. 전역 선언 `string 이름;`(또는 `= "기본값"`)으로 변수를 만듦. 처리 함수가 없으면 노드 ID 이름으로 값만 저장하고 다음 장.
- 표본(둘째 작품): 8장 성, 9장 이름 → 23·96·107·120장의 `$성;$이름;`에 표시.
- 원본은 입력값을 서버(앱북 저장)에도 보관했지만 웹 플레이어는 브라우저 메모리에만 둡니다(다른 파일 열기·새로고침 시 초기화).

### 원본과 다른 점 (의도적 단순화)

| 항목 | 원본 | 웹 플레이어 |
|---|---|---|
| 독자 설정 | 넘김 방식(문단/페이지/자동), 속도, 문단·페이지 대기 시간 설정 가능 | 기본값 고정(문단 모드, 속도 70) |
| 독자 글자 속도 | 앱 설정(기본 70 = 글자당 15ms) | 100 고정(한 줄씩 바로 표시) |
| 노드별 `speed` / `event` | 값이 있으면 독자 설정보다 우선 | `speed`는 반영, `event`는 아직 반영 안 함(표본 파일은 전부 비어 있음) |
| 클릭 대기 표시 | 깜빡이는 표시(caret) | 없음 |
| 이전 장 | 회상(flashback) 기능 | `←`로 이전 장을 처음부터 다시 출력 |
| 자동 넘김 장 클릭 | 확인 못 함 | 클릭하면 즉시 다음 장 |

## 음악

- 음원은 `.ucn`에 없습니다. 원본은 `http://kr.my.ucnovel.com/storage/music/` + 리소스 경로에서 스트리밍했고 서버는 종료됐습니다.
- Wayback Machine 확인 결과 표본 파일의 곡은 저장돼 있지 않았습니다.
- 그래서 해당 장의 BGM 리소스 이름만 `▶ 이름.mp3`로 표시합니다. 이름 끝의 `(1)` 같은 번호는 뗍니다.

## 로그

형식: `HH:MM:SS.mmm [수준] 메시지`. 수준은 `INFO`(정보), ` OK `(성공), `WARN`(경고), `ERR `(오류).
로그 창에서 `전체`/`경고·오류` 보기를 고를 수 있고, `복사`·`저장`은 현재 보기만 대상으로 합니다(경고·오류 저장 파일은 `<파일명>_log_경고오류.txt`).

### 불러오기
| 수준 | 메시지 | 의미 |
|---|---|---|
| INFO | `UCN Reader 시작 · <User-Agent>` | 페이지 시작, 브라우저 정보 |
| ERR | `이 브라우저는 압축 해제(DecompressionStream)를 지원하지 않습니다…` | 브라우저가 너무 오래됨 |
| INFO | `파일 열기: <이름> (<MB>)` | 파일 선택됨 |
| WARN | `확장자가 .ucn이 아닌 파일: … — 내용으로 판별해 열어 봅니다` | 이름이 바뀐 파일. 헤더로 판별해 계속 진행 |

## 테스트 기록

Chromium(Playwright)으로 표본 파일에 대해 확인한 항목:
- 엔트리 84개 해제, 목차 대조, 이미지 83장 모두 참조 일치, 콘솔 오류 없음
- 1~16장 자동 넘김 후 17장 도달, 19·30·56장의 줄바꿈·`#p`·`#w;` 클릭 대기 순서
- 레이어 합성(3·6·10·15·19장)이 추출 도구로 합성한 결과와 일치
- 사진 zip 83장이 추출 도구 결과와 바이트 단위로 같음, 글 txt 193장
- 잘린 파일: 39번째 엔트리에서 오류 기록 후 나머지로 재생 / 아무 데이터 파일: 첫 화면 오류 상자
- 데스크톱(1000~1200px)·휴대폰(390px) 화면

> 테스트 환경에 한글 로캘이 없으면 Chromium이 한글 다운로드 파일명을 `download`로 바꿉니다. 실제 브라우저에서는 정상입니다.
